The problem

One agent on one repo works. It stops working at project #4.

You can't see. Which of eight panes is asking for approval, and which finished ten minutes ago? You click through them one by one.
It doesn't remember. Every new session re-derives which project owns what, what was in flight, what was already tried.
It doesn't learn. The reflex fix is to paste one more paragraph into CLAUDE.md. Every lesson makes the prompt longer, until nothing in it fires reliably.
FleetMux

See which agent is waiting for you. Jump there with one key.

The bar reads ⬡ Claude 2 ●1 ◆ Codex 2 ●1: two Claude panes, one asking for approval; two Codex panes, one idle. Ctrl-q Enter goes to the next pane that needs you.

  • Detected by command, not title. Claude Code titles its pane with the conversation topic, Codex with the task — on a real server with 12 Claude and 16 Codex panes, exactly one title contained the word "claude". pane_current_command has no such ambiguity.
  • State read from the screen. "esc to interrupt" = busy; "Do you want to proceed?" = waiting for approval; neither = idle. 29 panes probe in 0.4 s.
  • One command installs everything — tmux, plugins, Starship, Nerd Font — and running it twice is a no-op (CI installs twice and diffs). fleetmux-doctor checks the setup; fleetmux-start claude codex launches the agents.
# install
bash <(curl -fsSL https://raw.githubusercontent.com/xiaolongnk/fleetmux/main/bin/install.sh)
# or just the status bar, in your own ~/.tmux.conf
set -g @plugin 'xiaolongnk/tmux-agent-status'
SuperHarness

One number to defend: the always-loaded tax.

Every line in CLAUDE.md is a tax paid on every session. SuperHarness splits every layer — rules, skills, memory, knowledge, task state — into a small index that always loads and a library that loads only on match. The library may grow without limit; the index must stay flat.

  • Portfolio, not task. A requirement comes in → the registry routes it to a project → that project's agent definition says how work is done there, its task board says what's in flight. The tier (personal / work) decides git and review policy; nothing is judged per task.
  • Lessons go into the library; the core doesn't grow. Correction → learn files it in the right layer → curate sediments what stopped earning its always-loaded place into knowledge/ → check proves the index didn't grow.
  • Falsifiable. superharness check measures the real loading surface and exits 1 when the tax grows, or when the registry, agent definitions, boards and memory index disagree.

npx create-superharness check
